# P01.08 — Health, Readiness & Diagnostics

- Phase: `P01`
- State: `active`
- Owner/domain: `kernel.operations`
- Depends on: `P01.07 done`
- Blocks: `P01.09`–`P01.12`
- Change class: `B`

> **Implementation authorization:** `kernel_code_authorized=true` for P01.08 only. `business_feature_code_authorized=false`. P01.08 is the sole active executable kernel scope.

## Objective

Provide bounded liveness/readiness/diagnostic primitives that expose operational state without leaking secrets or treating every dependency as equally critical.

## In scope

- liveness versus readiness semantics;
- dependency check registry with criticality classification;
- bounded timeouts/cancellation;
- startup/readiness transition model;
- safe diagnostic summary with stable machine states;
- build/version identity integration;
- observability integration from P01.07;
- test harness for healthy/degraded/unready dependency states;
- P01.01-P01.07 completed-package regression preservation;
- repository-wide Go quality verification;
- GitHub-hosted G0/G1/G2/G3/G5/G6/G7 evidence.

## Out of scope

P01.08 must not implement:

- public business status page;
- tenant/module health aggregation (`P03+`);
- SLO alerting/orchestration automation;
- Kubernetes-specific architecture beyond portable health semantics;
- privileged support diagnostics containing sensitive data;
- job/scheduler behavior owned by P01.09;
- feature registry owned by P01.10;
- audit transport owned by P01.11;
- developer CLI behavior owned by P01.12;
- identity/tenancy/module/event/workflow/business implementation;
- AI/LLM/model gateway, planner, memory/RAG, agents or autonomous execution.

## Security & reliability invariants

Health output must not expose connection strings, host secrets, credentials, SQL, object keys or sensitive payloads. Liveness answers whether the process can function; readiness answers whether it should receive applicable work. Optional dependency degradation must not automatically kill the process. Security-critical dependency failure must fail closed where its capability is required. Health/diagnostic output is operational evidence, not authorization, tenancy or business-state authority.

## Acceptance criteria

1. Liveness/readiness are semantically distinct and contract-tested.
2. Required dependency failure produces `unready`, not false success.
3. Optional dependency failure can produce explicit degraded state where policy allows.
4. Checks are timeout-bounded and cannot hang health evaluation.
5. Diagnostic output passes secret/sensitive-data negative tests.
6. No P03 module-health or business status functionality is introduced.
7. Completed P01.01-P01.07 regression verifiers remain PASS.
8. Repository-wide Go quality remains PASS.
9. Applicable G0/G1/G2/G3/G5/G6/G7 evidence is PASS on GitHub-hosted `ubuntu-24.04`.

## Completion evidence

Record healthy/unready/degraded/timeout tests, output-redaction evidence, exact dependency/tool versions where applicable, source SHA, workflow run/job, executing runner, completed-package regressions and merge SHA.

`FAIL`, `BLOCKED`, `NOT RUN` or `N/A` cannot be relabeled PASS for required P01.08 gates.
