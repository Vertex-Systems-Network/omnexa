## Objective

Provide bounded liveness/readiness/diagnostic primitives that expose operational state without leaking secrets or treating every dependency as equally critical.

## Implemented scope

- semantically distinct process liveness and dependency readiness;
- deterministic dependency check registry with `required`, `optional` and `security_critical` classifications;
- bounded timeout/cancellation handling and evaluation isolation;
- startup/ready/stopping/failed transition model;
- stable safe diagnostic summary with no raw provider/check error retention;
- build/version identity integration;
- P01.07 structured observability integration;
- healthy/degraded/unready dependency semantics;
- panic containment and deterministic ordering;
- race-safe registry/lifecycle access;
- P01.01-P01.07 completed-package regression preservation;
- repository-wide Go quality verification;
- GitHub-hosted G0/G1/G2/G3/G5/G6/G7 evidence.

## Security & reliability invariants retained

Health output must not expose connection strings, host secrets, credentials, SQL, object keys or sensitive payloads. Liveness answers whether the process can function; readiness answers whether it should receive applicable work. Optional dependency degradation must not automatically kill the process. Security-critical dependency failure fails closed where its capability is required. Health/diagnostic output is operational evidence, not authorization, tenancy or business-state authority.
