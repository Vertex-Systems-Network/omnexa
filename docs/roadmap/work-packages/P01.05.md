# P01.05 — Cache Abstraction

- Phase: `P01`
- State: `planned`
- Owner/domain: `kernel.cache`
- Depends on: `P01.04 done`
- Blocks: `P01.06`–`P01.12`
- Change class: `B`

> Specification-only while `kernel_code_authorized=false`.

## Objective

Provide a small Redis-compatible cache/coordination boundary with explicit keys, expiry, serialization and failure behavior so caching can improve performance without becoming a hidden source of authority or correctness.

## In scope

- cache interface and Redis-compatible provider adapter;
- namespaced/versioned key conventions;
- explicit TTL semantics;
- typed serialization boundary;
- get/set/delete and bounded atomic primitives required by the kernel;
- connection/config integration through P01.02;
- cache-miss versus provider-failure distinction;
- deterministic local/test fake only where semantics match the contract.

## Out of scope

- business-domain cache keys;
- sessions/authentication (`P02`);
- distributed job/event fabric (`P04` phase);
- generic distributed locks unless a concrete invariant requires them;
- using cache as system of record.

## Architecture & security invariants

Cache loss must not corrupt authoritative state. Tenant-sensitive future keys must include authoritative scope before use. RESTRICTED secrets/auth equivalents are prohibited as ordinary cached payloads unless a later approved security contract explicitly permits them. Provider outage must degrade/fail according to caller policy, never bypass authorization.

## Acceptance criteria

1. Key namespace/version and TTL behavior are deterministic.
2. Cache miss and provider error are distinguishable.
3. Serialization incompatibility fails safely.
4. Provider restart/flush cannot violate P01 correctness.
5. Tests prove bounded timeout/cancellation behavior.
6. No business/session/event semantics are implemented.
7. Applicable G0/G1/G2/G3/G5/G6/G7 evidence is PASS.

## Completion evidence

Record provider/test version, contract tests, outage/timeout tests, source SHA, workflow run/job and runner.
