# P01.01 — Go Workspace / Build Skeleton

- Phase: `P01`
- State: `active`
- Owner/domain: `kernel.platform`
- Depends on: `P00 done`, `P01 entry gate satisfied`
- Blocks: `P01.02`–`P01.12`
- Change class: `B`

> **Implementation authorization:** `kernel_code_authorized=true` for this package only. `business_feature_code_authorized=false`. P01.01 is the sole active executable scope.

## 1. Objective

Create the minimum reproducible Go workspace/build foundation for Omnexa Kernel without introducing business-domain behavior, persistence, tenancy, module runtime, workflow, product APIs or later P01 capabilities.

P01.01 establishes structure before behavior: repository-owned Go toolchain/version declaration, deterministic build/test entry points, a minimal kernel process skeleton, build/source metadata and hosted CI evidence from a clean checkout.

## 2. In scope

- repository-owned Go version/toolchain declaration consistent with `TOOLCHAIN_STANDARD.md`;
- root Go workspace/module layout required by the modular-monolith architecture;
- `kernel/` executable/library skeleton with no business capability implementation;
- deterministic format, vet/static, unit-test, build and smoke commands;
- build metadata/version package sufficient to identify source/version without secrets;
- minimal process entrypoint that starts and exits cleanly without external infrastructure;
- baseline tests proving the skeleton builds and runs;
- ignore rules for Go build/test artifacts;
- CI integration on the canonical GitHub-hosted `ubuntu-24.04` governance lane;
- initial canonical verification wrapper/command mapping for applicable P01.01 gates.

Initial target source shape:

```text
go.work
go.mod
kernel/
├── cmd/
│   └── omnexa/
│       └── main.go
└── internal/
    └── buildinfo/
```

The exact package split may be adjusted only within this package boundary.

## 3. Explicitly out of scope

P01.01 must not implement:

- configuration/environment system (`P01.02`);
- structured application error/result model (`P01.03`);
- PostgreSQL/migrations (`P01.04`);
- Redis/cache (`P01.05`);
- object/file storage (`P01.06`);
- OpenTelemetry/structured logging (`P01.07`);
- health/readiness endpoints (`P01.08`);
- jobs/scheduler (`P01.09`);
- feature flags/config registry (`P01.10`);
- audit transport (`P01.11`);
- full developer CLI (`P01.12`);
- HTTP business APIs;
- authentication, tenancy or organizations (`P02`);
- module runtime (`P03`);
- any business module;
- production Docker/Kubernetes packaging.

## 4. Architecture boundary

- Owner: `kernel.platform` / repository build foundation.
- Data/schema owner: none.
- Database migrations: none.
- Public business APIs: none.
- Events/workflows: none.
- External infrastructure dependencies: none.
- Third-party dependencies: standard library first; additions require explicit justification and supply-chain review.

No global super-admin/backdoor concept, tenant assumption, local workstation path, credential or secret may be embedded in the skeleton or metadata.

## 5. Failure, security and reproducibility

- compiler/build/test/static failure returns non-zero;
- no startup wait on PostgreSQL, Redis, NATS or S3;
- process startup/exit is deterministic;
- builds must not shell out to unpinned remote installers;
- generated/version metadata must not expose local usernames, paths or credentials;
- build/source identity must be deterministic enough to trace the source commit/version;
- canonical verification runs on GitHub-hosted Linux only; no self-hosted/local runner fallback.

## 6. Acceptance criteria

1. **AC-01** — Clean checkout with the repository-declared Go toolchain runs documented P01.01 verification commands without hidden setup.
2. **AC-02** — Workspace/module graph contains only kernel/build-skeleton scope and no business-domain package.
3. **AC-03** — `go test` for P01.01 passes from zero.
4. **AC-04** — formatting and `go vet`/chosen static baseline pass.
5. **AC-05** — Omnexa kernel skeleton builds on GitHub-hosted `ubuntu-24.04` without platform-specific local assumptions.
6. **AC-06** — Built process starts/exits deterministically without PostgreSQL, Redis, NATS or object storage.
7. **AC-07** — Build/version metadata identifies source/version without secret or local-path leakage.
8. **AC-08** — No database schema/migration, tenancy/authz implementation, module runtime or business functionality is introduced.
9. **AC-09** — Applicable `G0`, `G1`, `G2` and `G7` checks produce `PASS`; `BLOCKED`, `NOT RUN` and `N/A` are never relabeled PASS.
10. **AC-10** — State/status/ledger are reconciled only after executable acceptance evidence passes.

## 7. Required tests / evidence

Required:

- Go formatting check;
- `go vet` / initial static baseline;
- unit test for build/version metadata;
- process smoke test;
- build compilation;
- dependency/scope check preventing accidental business/module imports;
- clean-checkout hosted build/test;
- GitHub-hosted `ubuntu-24.04` governance execution with `RUNNER_ENVIRONMENT=github-hosted`.

N/A in P01.01 and must be recorded as such: tenant isolation, authorization matrices, DB migrations, event replay/idempotency, module lifecycle and external integration E2E.
