## Objective

Implement non-human service principals and bounded API credential lifecycle without representing automation as fake human users or pulling OAuth developer applications forward.

## In scope

- Service Account as a distinct non-human principal under `kernel.identity`;
- tenant/organization binding and capability/permission scope composition through existing P02 authorization foundations;
- API credential issue/identify/verify/rotate/revoke/expire lifecycle;
- one-time secret presentation where applicable and non-reversible verifier storage;
- credential metadata safe for inventory/audit while raw secrets remain RESTRICTED;
- last-used/rotation metadata only where classification-safe and useful;
- positive scope tests plus wrong-tenant/wrong-scope/revoked/expired negative tests.

## Out of scope

- OAuth developer applications owned later by `platform.developer`;
- external connector/provider integration (`P16`);
- device identities/POS (`P11`);
- AI agent execution identity behavior (`P19-P20`);
- business API scopes.

## Security and architecture invariants

- non-human principals are never fake human Users;
- raw API credentials are `RESTRICTED`, not logged, traced, audited or stored reversibly;
- credentials are least-privilege, rotatable, revocable and tenant/org bound;
- credential possession does not bypass current authorization state;
- no generic platform superkey/master-token mechanism.

## Acceptance criteria

1. service-account lifecycle is distinct from User lifecycle while sharing canonical principal semantics.
2. issued credential authenticates only its service principal and allowed tenant/org scope.
3. wrong tenant/scope, revoked and expired credentials fail closed.
4. rotation invalidates superseded credentials according to documented semantics.
5. raw credentials are absent from persistence/logs/traces/errors/audit after allowed one-time issuance surface.
6. no OAuth developer app/integration/business scope is introduced.
7. migrations, Go quality and prior regressions pass as applicable.
8. applicable G0-G8 evidence runs on canonical GitHub-hosted `ubuntu-24.04`.
