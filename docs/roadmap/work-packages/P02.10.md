## Objective

Complete P02 by integrating security-significant identity/tenancy/organization/authorization activity with the P01 audit transport and proving the full P02 isolation/permission/session exit gate on canonical GitHub-hosted CI.

## In scope

- attributable audit records for material identity/session/tenant/org/role/policy/service-account/settings security operations;
- classification-safe actor/action/target/scope/outcome/correlation/reason metadata using the existing `kernel.audit` boundary;
- explicit required-audit failure semantics for privileged operations where correctness requires audit;
- P02 aggregate verification that composes completed package verifiers rather than duplicating them;
- final integration/security evidence for cross-tenant isolation, object/scope permission behavior, role differences, service-account scoping and session invalidation;
- fresh + supported-upgrade migration proof for the P02 schema baseline;
- P01.01-P01.12 regression preservation, repository Go quality and applicable G0-G8 evidence.

## Out of scope

- generic audit read/export/admin UI;
- support impersonation product surface;
- P03 module runtime/permission registration;
- business domains or business-feature audit catalogs;
- P04 events/workflows;
- AI/model/agent behavior.

## Security and architecture invariants

- audit is separate from ordinary logs and stores no credentials/authentication factors/secrets;
- audit write does not imply audit read/export authority;
- privileged security mutations cannot silently claim success when required audit fails;
- cross-tenant and privilege-escalation failures are release blockers;
- no P03 activation is implied by P02 completion.

## Acceptance criteria

1. material identity/session/tenant/org/role/policy/service-account/settings operations emit attributable classification-safe audit evidence where required.
2. required-audit failure behavior is explicit and fail-closed for protected mutations where specified.
3. canonical tests prove same-tenant success and cross-tenant denial.
4. canonical tests prove object/org/scope permission allow/deny and role differences.
5. canonical tests prove service-account scope, revocation/expiry and no-secret behavior.
6. canonical tests prove required session invalidation/revocation behavior.
7. fresh and supported-upgrade P02 migrations pass without manual database edits.
8. repository Go quality, P01.01-P01.12 and P02.01-P02.09 regressions pass.
9. applicable G0-G8 evidence passes on canonical GitHub-hosted `ubuntu-24.04`.
10. completion evidence is recorded before P02 is reconciled done; P03 remains planned until a separate transition.

## Completion evidence

Activation is not completion evidence. Exact implementation SHA/PR/run/job, runner identity, migration evidence, cross-tenant/authz/service-account/session evidence and accurate G0-G8 states are recorded only after observed execution in a later governed P02.10 implementation session.

## State transition

`planned -> active -> verification -> done`; current state is `active`. After P02.10 implementation acceptance, a separate P02 closure must satisfy `docs/governance/P02_EXIT_GATE.md`; P03 does not activate implicitly.
