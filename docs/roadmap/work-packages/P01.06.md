# P01.06 — Object & File Storage Abstraction

- Phase: `P01`
- State: `planned`
- Owner/domain: `kernel.storage`
- Depends on: `P01.05 done`
- Blocks: `P01.07`–`P01.12`
- Change class: `B`

> Specification-only while `kernel_code_authorized=false`.

## Objective

Provide a governed S3-compatible object/file storage boundary with explicit object identity, metadata, streaming, integrity and deletion semantics, without introducing CMS/media/business behavior.

## In scope

- S3-compatible provider interface/adapter;
- bucket/container configuration boundary;
- object key namespace/version conventions;
- streaming upload/download APIs with bounded memory behavior;
- content length/type metadata handling as untrusted input;
- integrity metadata/checksum hooks;
- put/get/head/delete primitives;
- provider timeout/cancellation/error mapping;
- test provider/harness with contract-equivalent behavior.

## Out of scope

- media library/CMS/file UI;
- public URL policy, CDN, image processing or thumbnails;
- tenant document models;
- malware scanning implementation beyond future hook boundary;
- retention/legal hold semantics owned by later data/governance capabilities.

## Security invariants

Object keys never imply authorization. Callers must supply authorized scope later. Path traversal/file-name input cannot escape provider namespace. Credentials are RESTRICTED. Logs/errors must not expose signed URLs, secrets or sensitive object content. Downloads/uploads are streamed and size-bounded by explicit caller policy.

## Acceptance criteria

1. Provider contract tests cover put/get/head/delete and missing-object behavior.
2. Large-object tests prove streaming rather than whole-file buffering.
3. Invalid metadata/key input fails safely.
4. Provider timeout/unavailability is bounded and classified.
5. Integrity metadata can detect corrupted/mismatched content where supported.
6. No CMS/media/business object model is introduced.
7. Applicable G0/G1/G2/G3/G5/G6/G7 evidence is PASS.

## Completion evidence

Record provider/test version, streaming/integrity/negative tests, source SHA, workflow run/job and runner.
