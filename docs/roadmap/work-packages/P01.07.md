# P01.07 — Structured Logging & OpenTelemetry Baseline

- Phase: `P01`
- State: `active`
- Owner/domain: `kernel.observability`
- Depends on: `P01.06 done`
- Blocks: `P01.08`–`P01.12`
- Change class: `B`

> **Implementation authorization:** `kernel_code_authorized=true` for P01.07 only. `business_feature_code_authorized=false`. P01.07 is the sole active executable kernel scope.

## Objective

Implement one structured observability baseline for kernel processes using OpenTelemetry-compatible tracing/metrics boundaries and safe structured logs, without making telemetry a correctness dependency.

## In scope

- structured logger with stable field conventions;
- log levels and environment-appropriate defaults;
- correlation/trace context propagation helpers;
- OpenTelemetry resource/service identity baseline;
- trace and metric provider lifecycle;
- exporter/configuration boundary with no vendor lock-in;
- safe shutdown/flush behavior;
- redaction/filtering hooks aligned with data classification;
- test capture utilities for deterministic assertions;
- P01.01-P01.06 completed-package regression preservation;
- repository-wide Go quality verification;
- GitHub-hosted G0/G1/G2/G3/G5/G6/G7 evidence.

## Out of scope

P01.07 must not implement:

- product analytics/business metrics;
- dashboards/alerts/SLO automation;
- domain-specific spans/metrics;
- audit log semantics (`P01.11`);
- vendor-specific proprietary instrumentation;
- health/readiness behavior owned by P01.08;
- scheduler, feature registry or audit transport owned by later P01 packages;
- identity/tenancy/module/event/workflow/business implementation;
- AI/LLM/model gateway, planner, memory/RAG, agents or autonomous execution.

## Security invariants

Secrets, auth tokens, private keys, raw `RESTRICTED` payloads and ordinary sensitive business content are prohibited from logs/telemetry by default. Observability outage must not bypass security or corrupt business state. Correlation IDs are identifiers, not authorization credentials. Telemetry remains diagnostic infrastructure and must not become an alternate source of authoritative business state.

## Acceptance criteria

1. Structured records include stable timestamp/severity/service/context fields.
2. Trace/correlation context propagates through kernel call boundaries.
3. Redaction negative tests prevent prohibited secret/sensitive values from emission.
4. Exporter failure is bounded and cannot prevent safe process shutdown beyond explicit limits.
5. Telemetry can be disabled/test-captured without changing application semantics.
6. Audit events are not conflated with ordinary logs.
7. Completed P01.01-P01.06 regression verifiers remain PASS.
8. Repository-wide Go quality gate remains PASS.
9. Applicable G0/G1/G2/G3/G5/G6/G7 evidence is PASS on GitHub-hosted `ubuntu-24.04`.

## Completion evidence

Record structured-log tests, redaction tests, trace/metric lifecycle tests, exporter failure evidence, exact dependency/tool versions, source SHA, workflow run/job, executing runner, completed-package regressions and merge SHA.

`FAIL`, `BLOCKED`, `NOT RUN` or `N/A` cannot be relabeled PASS for required P01.07 gates.

`active -> verification -> done` only after all acceptance evidence passes. Completion unlocks **only P01.08 — Health, readiness & diagnostics**. P01.08+, P02+ and business-feature implementation remain unauthorized until their own governed transitions.
