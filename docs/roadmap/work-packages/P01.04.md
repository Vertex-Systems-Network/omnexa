# P01.04 — PostgreSQL Connection & Migration Foundation

- Phase: `P01`
- State: `planned`
- Owner/domain: `kernel.data`
- Depends on: `P01.03 done`
- Blocks: `P01.05`–`P01.12`
- Change class: `B`

> Specification-only while `kernel_code_authorized=false`.

## Objective

Establish the governed PostgreSQL connectivity and migration substrate that later kernel capabilities/modules can consume without sharing ownership of each other's schemas or relying on hidden manual SQL.

## In scope

- PostgreSQL connection/pool construction from P01.02 configuration;
- bounded startup/connectivity behavior and safe provider error mapping;
- transaction helper boundary without domain writes;
- migration runner/version ledger foundation;
- deterministic fresh-install and upgrade execution;
- advisory/coordination strategy preventing conflicting migration execution where required;
- repository conventions for owner-scoped migrations;
- test database lifecycle using synthetic data only.

## Out of scope

- tenant/organization tables (`P02`);
- module runtime migrations/ownership registry (`P03`);
- event outbox/inbox (`P04` phase);
- business schemas;
- cross-module SQL access;
- backups/HA production topology.

## Architecture & security invariants

PostgreSQL remains OLTP source of truth. Every future schema/write model has one authoritative owner. Migrations are versioned, reviewable and reproducible; no startup path silently mutates unrelated owner schemas. Credentials are RESTRICTED and never logged. Tests must never require production data.

## Acceptance criteria

1. Fresh empty database migrates deterministically from zero.
2. Re-running migrations is safe and does not duplicate effects.
3. Upgrade path from a prior fixture version succeeds deterministically.
4. Failed migration reports safe structured failure and does not claim success.
5. Connection exhaustion/timeouts are bounded and testable.
6. No tenant/module/business tables are introduced by this package.
7. Applicable G0/G1/G2/G3/G4/G5/G7 evidence is PASS.

## Completion evidence

Record PostgreSQL version, fresh/upgrade migration test IDs, schema/version ledger evidence, negative failure evidence, source SHA, workflow run/job and runner.

## State transition

`planned -> active` only after P01.03 `done`; completion unlocks only P01.05.
