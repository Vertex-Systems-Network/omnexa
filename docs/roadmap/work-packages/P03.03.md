# P03.03 — Dependency Graph Resolver

- Phase: `P03`
- State: `planned`
- Owner/domain: `kernel.modules`
- Depends on: `P03.02`
- Blocks: `P03.04`
- Change class: `B`

> Readiness only. `business_feature_code_authorized=false`; no dependency runtime implementation before canonical activation.

## Objective

Implement deterministic module dependency validation/resolution that machine-enforces `MODULE_STANDARD.md` and `DEPENDENCY_MATRIX.md` required, optional, platform and forbidden dependency semantics.

## In scope

- version-aware required and optional dependency resolution;
- platform dependency validation;
- deterministic topological order for valid required graphs;
- cycle and incompatible-version detection;
- undeclared/forbidden/private dependency detection hooks that can be proven by reference fixtures;
- selective optional-dependency degradation metadata for later lifecycle/capability availability decisions.

## Out of scope

- lifecycle mutations;
- package installation/download;
- P04 event dependency orchestration;
- full System Graph runtime or trust/advisory scanning.

## Security and architecture invariants

- circular required dependencies are release-blocking invalid state;
- missing/incompatible required dependency fails closed;
- missing optional dependency cannot make unrelated modules fail globally;
- resolver output does not authorize capability calls or database access;
- kernel may not depend on business modules and direct cross-module private imports/writes remain forbidden;
- resolution is deterministic for identical registry/manifests.

## Acceptance criteria

1. required dependency presence/version is enforced before install/enable eligibility.
2. optional absence produces explicit selective-degradation data rather than global failure.
3. cycles, incompatible constraints and undeclared/forbidden dependency fixtures are rejected deterministically.
4. valid graph produces stable ordering independent of discovery enumeration order.
5. tests include required, optional, platform, cycle, conflict and forbidden-path scenarios.
6. no resolver path grants authority or accesses another module's private schema/package.
7. Go quality plus P01/P02 regressions pass on GitHub-hosted `ubuntu-24.04`.

## Completion evidence

None while planned. Future completion requires exact-head dependency resolver verifier evidence.

## State transition

`planned -> active -> verification -> done`; P03.04 remains planned until separate transition.
