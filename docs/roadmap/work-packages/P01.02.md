# P01.02 — Configuration & Environment System

- Phase: `P01`
- State: `active`
- Owner/domain: `kernel.platform`
- Depends on: `P01.01 done`
- Blocks: `P01.03`–`P01.12`
- Change class: `B`

> **Implementation authorization:** `kernel_code_authorized=true` for this package only. `business_feature_code_authorized=false`. P01.02 is the sole active executable scope.

## Objective

Provide one typed, deterministic configuration system for Omnexa processes so local, CI, test and deployed environments resolve settings consistently without embedding secrets or business-domain behavior.

## In scope

- typed configuration loading and validation;
- explicit precedence for defaults, config files and environment variables;
- environment identity (`local`, `test`, `staging`, `production` or governed equivalents);
- required/optional setting semantics;
- safe redaction for secret-classified values;
- startup failure on invalid required configuration;
- deterministic test overrides without global hidden state;
- configuration provenance diagnostics that reveal source category but never secret value;
- naming aligned with `CONFIGURATION_STANDARD.md`.

## Out of scope

- dynamic feature flags/config registry (`P01.10`);
- secret-manager/KMS provider integrations beyond a stable boundary;
- database/cache/storage client construction (`P01.04`–`P01.06`);
- structured application error/result conventions beyond minimal local config errors (`P01.03`);
- tenant-scoped settings (`P02+`);
- module runtime (`P03`);
- business-module configuration.

## Security invariants

Secrets are never committed, logged, returned in diagnostics, exposed through error payloads or copied into generated artifacts. Production-sensitive defaults must fail closed rather than silently downgrade security. Environment selection must not grant authorization or bypass policy. Test overrides must be explicit and isolated per configuration instance; no package-global mutable state may be introduced.

## Acceptance criteria

1. Clean checkout resolves a deterministic non-secret local/test configuration.
2. Invalid/missing required settings fail startup with safe actionable errors.
3. Precedence rules are executable and contract-tested.
4. Secret values are redacted in errors/diagnostics/tests.
5. Tests prove environment overrides do not leak across test cases.
6. Configuration provenance reports only source category/key metadata, never secret values.
7. No P01.03+ capability or business configuration is implemented.
8. Applicable `G0`, `G1`, `G2`, `G5`, `G7` evidence is PASS through the required GitHub-hosted `governance` lane.

## Required tests

- default/local/test resolution;
- environment-variable override precedence;
- config-file precedence where implemented by this package;
- required-setting missing/invalid negative tests;
- invalid environment identity negative test;
- secret redaction in diagnostics/errors;
- independent loader instances prove no cross-test/global-state leakage;
- kernel startup/config construction smoke test without PostgreSQL, Redis, NATS or S3;
- dependency/scope guard proving no P01.03+ or business package import.
