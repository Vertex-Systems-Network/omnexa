# P01.11 — Audit Transport Foundation

- Phase: `P01`
- State: `planned`
- Owner/domain: `kernel.audit`
- Depends on: `P01.10 done`
- Blocks: `P01.12`
- Change class: `B`

> Specification-only while `kernel_code_authorized=false`.

## Objective

Provide the protected transport/envelope boundary for future security and business audit records so privileged actions can emit tamper-evident, classification-aware audit facts without conflating them with ordinary logs or prematurely defining domain audit events.

## In scope

- stable audit record envelope aligned with P00 security standard;
- actor/action/target/scope/outcome/correlation/reason/approval metadata slots;
- append-oriented sink interface and failure semantics;
- classification/redaction enforcement boundary;
- immutable timestamp/identifier conventions;
- explicit support for impersonation/privileged-action metadata;
- local/test sink for deterministic assertions;
- observability of audit transport health without logging protected payloads.

## Out of scope

- P02 user/tenant/role audit catalog;
- business-domain audit event definitions;
- compliance export/reporting UI;
- long-term legal retention/hold implementation;
- replacing domain events with audit records.

## Security & reliability invariants

Protected audit is separate from ordinary logs. Audit failure cannot silently claim success for operations whose policy requires durable audit; callers must receive explicit failure/degradation semantics. Records must not contain secrets/auth equivalents by default. Audit write access does not imply audit read/export authority.

## Acceptance criteria

1. Envelope requires actor/action/target/scope/outcome/correlation fields appropriate to the operation.
2. Audit records are append-oriented and immutable through the public interface.
3. Negative tests reject secret/prohibited payload fields.
4. Required-audit sink failure propagates explicit failure rather than silently dropping the record.
5. Impersonation/reason/approval metadata can be represented without P02 identity implementation.
6. Audit and application logging remain separate contracts.
7. Applicable G0/G1/G2/G3/G5/G6/G7 evidence is PASS.

## Completion evidence

Record envelope/schema tests, redaction/required-sink-failure tests, source SHA, workflow run/job and runner.

## State transition

`planned -> active` only after P01.10 `done`; completion unlocks only P01.12.
