# P01.03 — Structured Error & Result Conventions

- Phase: `P01`
- State: `active`
- Owner/domain: `kernel.platform`
- Depends on: `P01.02 done`
- Blocks: `P01.04`–`P01.12`
- Change class: `B`

> **Implementation authorization:** `kernel_code_authorized=true` for this package only. `business_feature_code_authorized=false`. P01.03 is the sole active executable scope.

## Objective

Implement the frozen P00 error semantics as reusable Go primitives so kernel and later modules can distinguish machine-stable failures from safe public detail without leaking internal causes.

## In scope

- typed/stable machine error codes;
- safe public message/detail separated from private diagnostic cause;
- wrapping/unwrapping without losing classification;
- explicit retryability/failure-category metadata where justified;
- deterministic bounded validation-field errors;
- request/correlation trace attachment boundary without telemetry emission;
- transport-neutral result/error primitives suitable for later HTTP/jobs/events adapters;
- helpers preserving standard `errors.Is` / `errors.As` semantics where appropriate;
- regression compatibility with completed P01.01/P01.02 behavior;
- GitHub-hosted verifier and negative security tests.

## Explicitly out of scope

P01.03 must not implement:

- HTTP Problem Details transport adapter beyond stable hooks;
- PostgreSQL/provider-specific error mapping (`P01.04+`);
- cache/storage errors owned by later packages;
- logging/OpenTelemetry emission (`P01.07`);
- health/readiness endpoints;
- job/scheduler behavior;
- tenant/authz/module-runtime concerns;
- domain/business error catalogs or business APIs.

## Security invariants

Stack traces, SQL, secrets, credentials, private keys, raw provider payloads, local filesystem paths and sensitive tenant/business data must never enter the public error representation. Internal causes remain private to authorized diagnostic consumers introduced by later packages.

Error codes are machine-stable identifiers, not localized prose. Retryability is explicit metadata, never inferred from message text. Correlation identifiers are metadata only and cannot grant authority.

## Acceptance criteria

1. Stable code and safe public message survive wrapping.
2. `errors.Is`/`errors.As` semantics remain usable for wrapped causes/classified errors.
3. Negative tests prove private cause/secret text cannot reach public representation.
4. Validation failures have deterministic bounded field structure and duplicate/ordering rules.
5. Retryable/non-retryable semantics are explicit and testable.
6. Result/error primitives contain no HTTP, persistence, telemetry or business-domain coupling.
7. P01.01 and P01.02 regression verifiers continue to pass.
8. Applicable G0/G1/G2/G5/G7 evidence passes on GitHub-hosted `ubuntu-24.04`.
