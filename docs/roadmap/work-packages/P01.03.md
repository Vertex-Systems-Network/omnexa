# P01.03 — Structured Error & Result Conventions

- Phase: `P01`
- State: `planned`
- Owner/domain: `kernel.platform`
- Depends on: `P01.02 done`
- Blocks: `P01.04`–`P01.12`
- Change class: `B`

> Specification-only while `kernel_code_authorized=false`.

## Objective

Implement the frozen P00 error semantics as reusable Go primitives so kernel and later modules can distinguish machine-stable failures from safe user-facing detail without leaking internals.

## In scope

- typed/stable machine error codes;
- safe public message/detail versus private diagnostic cause;
- wrapping/unwrapping without losing classification;
- retryability and failure-category metadata where justified;
- validation-field errors using bounded structured detail;
- request/correlation trace attachment boundary;
- transport-neutral result/error primitives suitable for later HTTP/jobs/events adapters;
- helpers that preserve `errors.Is`/`errors.As`-style semantics where appropriate.

## Out of scope

- HTTP Problem Details adapter implementation beyond shared contract hooks;
- database/provider-specific error mapping (`P01.04+`);
- logging/telemetry emission (`P01.07`);
- domain/business error catalogs.

## Security invariants

Stack traces, SQL, secrets, credentials, private keys, raw provider payloads and sensitive tenant data never become public error content. Internal causes remain observable only through authorized diagnostics/telemetry paths introduced later.

## Acceptance criteria

1. Stable code and safe message survive wrapping.
2. Negative tests prove sensitive internal cause text cannot reach the public representation.
3. Validation failures have deterministic bounded field structure.
4. Retryable/non-retryable semantics are explicit rather than inferred from message text.
5. Result/error primitives contain no transport, persistence or business-domain coupling.
6. Applicable G0/G1/G2/G5/G7 evidence is PASS.

## Completion evidence

Record unit tests for wrapping, code stability, redaction and validation shape; static/build evidence; source SHA; workflow run/job and runner.

## State transition

`planned -> active` only after P01.02 `done`; `done` unlocks only P01.04.
