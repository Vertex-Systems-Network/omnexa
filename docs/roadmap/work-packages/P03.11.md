# P03.11 — Package Trust Hooks & P03 Exit Proof

- Phase: `P03`
- State: `planned`
- Owner/domain: `kernel.modules`
- Depends on: `P03.10`
- Blocks: `P03 exit`
- Change class: `B`

> Readiness only. `kernel_code_authorized=false` and `business_feature_code_authorized=false`; this package does not authorize `XTRUST-100`, marketplace or P04 implementation.

## Objective

Finish P03 by defining minimal package trust/provenance hook contracts required for later marketplace/trust maturity and by proving the complete module-runtime exit gate with isolated reference modules on canonical CI.

## In scope

- typed optional hook/metadata interfaces for publisher identity, package signature/provenance, SBOM identity and declared capability/data/network/secret profile;
- explicit distinction between metadata/hook presence and actual trust/certification decision;
- reference test modules and aggregate P03 verification composing P03.01-P03.10 behavior;
- P03 exit proof for dependency, lifecycle, upgrade/migration, forbidden-coupling, health/state and unrelated-module isolation;
- exact-head completion evidence plus repository Go quality/P01/P02 regressions and applicable G0-G8 evidence.

## Out of scope

- publisher onboarding or signature trust roots;
- dependency advisory/license enforcement;
- sandbox/network/secret/file brokers, resource quotas or kill-switch runtime;
- marketplace/package distribution;
- Product Federation/System Graph/Performance Intelligence runtime;
- P04 events/jobs fabric, business domains or AI/model/agent runtime.

## Security and architecture invariants

- hook metadata never means a package is trusted/certified;
- untrusted package code is not executed merely to discover/verify metadata;
- first-party/reference packages remain subject to the same public-boundary and ownership rules;
- required dependency failure and forbidden coupling fail closed;
- disable is non-destructive; purge is explicit/authorized/audited/dependency-checked;
- migration ownership and tenant boundaries remain enforced;
- health and evidence are classification-safe;
- completion cannot be claimed from AI-authored PASS text without canonical GitHub-hosted exact-head evidence.

## Acceptance criteria

1. package trust/provenance/SBOM/scope hook contracts are typed/versioned and clearly non-authoritative until future `XTRUST-100` activation.
2. reference modules prove **required dependency enforcement**.
3. reference modules prove **optional dependency degradation** without global boot failure.
4. reference modules prove **safe disable/re-enable** with preserved required data/history.
5. reference modules prove a supported **upgrade/migration path** without manual repair or cross-owner mutation.
6. canonical negative fixtures prove **forbidden cross-module dependency detection**, including private coupling/cycles where applicable.
7. canonical diagnostics prove **health/state accuracy** for healthy/degraded/unavailable/lifecycle states.
8. lifecycle/install/disable/detach/purge/failure fixtures prove **no unrelated module corruption**.
9. P03.01-P03.10 verifiers, repository Go quality and all P01/P02 regressions pass.
10. applicable G0-G8 evidence passes on canonical GitHub-hosted `ubuntu-24.04`; completion evidence records exact PR/head/run/job/environment.
11. P03 exit is reconciled only after evidence exists; P04 remains planned until a separate governed transition.
