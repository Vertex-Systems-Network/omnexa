## Accepted design decision

P03.06 preserves manifest schema v1/v2. Existing `capabilities_provided` / `capabilities_consumed` declarations remain bounded identifiers and are copied into the package-private validated manifest snapshot so capability registration consumes the same validated discovery provenance that established module identity.

Capability declarations are normalized into stable capability identity plus a positive bounded major version. Provider records retain discovered module/owner identity; consumer declarations resolve deterministically against compatible stable capability ID + major version.

Authorization requirement, trusted tenant/organization scope requirement and public contract references are descriptive metadata only. They do not create permission, raw tenant/org scope, handler exposure or invocation authority.

Runtime availability is derived from accepted P03.04 lifecycle state. Only enabled providers are active. Unavailable states preserve historical/discovered capability identity without being reported active.
