## Implemented contract

P03.08 now provides a deterministic declarative UI-contribution metadata boundary without introducing rendering, frontend authorization or future Experience/Portal/Product Federation runtime:

- validated schema-v1/v2 manifest snapshots retain declared `ui_slots` provenance;
- stable contribution identity is module/owner/ID/slot/kind/contract-version metadata;
- slots must be declared by the owning validated module snapshot;
- permission requirements may reference only owning-module declared permissions and remain non-granting;
- feature-flag conditions may reference only owning-module declared flags and remain configuration metadata;
- optional-dependency conditions must reference owning-module declared optional dependencies;
- contribution availability is bounded by module lifecycle state;
- schema-v2 missing, incompatible or non-enabled optional dependencies selectively degrade only affected contributions;
- schema-v1 optional dependency conditions without version contracts degrade safely as unresolved;
- fallback is bounded declarative metadata only;
- contribution metadata carries no executable handler/component/render callback, unrestricted payload, raw tenant/org authority, secret or database shortcut.
