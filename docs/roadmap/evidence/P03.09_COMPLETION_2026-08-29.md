## Implemented contract

P03.09 now provides deterministic execution-free migration ownership/planning metadata around the retained P01 migration foundation:

- migration identity binds module ID, module version, authoritative owner, declaration and positive owner-version ledger order;
- duplicate declarations, duplicate identities and owner/version order conflicts fail closed;
- authoritative owner and target owner must match validated module ownership;
- compatible, backfill and destructive change classes are explicit;
- backfill/destructive declarations require bounded strategy and recovery references;
- fresh-install plans are deterministic and owner/version ordered;
- supported-upgrade plans use declared module-version introduction metadata and reject future/invalid source versions;
- metadata contains no raw SQL, arbitrary filesystem path, execution callback, secret, tenant ID or organization ID authority;
- P01 remains the sole SQL executor, immutable checksum ledger, owner advisory-lock and transactional retry/double-apply authority.
