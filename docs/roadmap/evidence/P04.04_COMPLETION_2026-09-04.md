## Accepted implementation boundary

The accepted P04.04 implementation remains provider-neutral and closes only the producer-side local-database-to-event crash window on top of accepted P04.01-P04.03 behavior:

- canonical P04.01 event identity/envelope is retained unchanged through outbox enqueue and relay;
- an authorized owner mutation and required outbox enqueue can participate in the same local PostgreSQL transaction instead of silently opening a second transaction;
- owner mutation failure/rollback prevents the corresponding outbox event from becoming committed relay-visible state;
- conflicting reuse of one canonical EventID fails closed while exact same-event retry can be treated deterministically as unchanged;
- committed pending outbox state is recoverable after process restart without reconstructing the canonical event from mutable business state;
- relay uses the accepted provider-neutral P04.02 publication boundary;
- publication failure leaves the event pending/recoverable and does not create a false published mark;
- publish success followed by mark failure preserves the explicit duplicate-publication window and therefore does not claim exactly-once delivery;
- optimistic publication-state compare-and-set semantics prevent state corruption under concurrent relays while still allowing duplicate publication where the accepted at-least-once model permits it;
- producer/owner/tenant scope remains fail-closed and one scope cannot read/mark/rebind another scope's outbox state;
- owner-scoped PostgreSQL migration execution remains under the retained P01 migration runner/ledger and P03.09 ownership boundary;
- the accepted verifier checks Go quality, focused outbox tests, full retained event-package regressions, `go vet`, race tests and kernel build against real PostgreSQL CI state.

An outbox row, event ID, relay state, publication result, checkpoint, tenant value or transport identity grants no authorization or cross-module write authority.
