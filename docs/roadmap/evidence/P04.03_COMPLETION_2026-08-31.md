## Accepted boundary

The accepted implementation remains provider-neutral and establishes only the bounded P04.03 durability/checkpoint contract on top of accepted P04.01/P04.02 behavior:

- accepted P04.02 owner, stable consumer identity and event-route registration are reused rather than replaced by a competing identity model;
- durable progress is bound to explicit logical stream/partition-equivalent scope and trusted tenant scope where the P04.02 registration is tenant-scoped;
- `CheckpointStore` is a provider-neutral persistence seam; no database, broker or provider is selected by P04.03;
- checkpoint state is consumption progress only and contains bounded position plus event identity, never event payload/secrets or authorization capability;
- the empty-checkpoint resume convention is explicit: the first processable position is `1`;
- checkpoint advancement is contiguous and monotonic within one explicit durable scope;
- stale/regressive/gapped/conflicting advancement fails deterministically before unacknowledged work can be skipped;
- the accepted handler must succeed before checkpoint advancement is attempted;
- failed or cancelled handling cannot advance the checkpoint;
- restart/resume reads the last accepted checkpoint rather than guessing an implicit cursor;
- handler-success/checkpoint-write-failure deliberately leaves duplicate replay possible after restart, preserving at-least-once-compatible semantics;
- concurrent same-scope same-position work may duplicate handler execution, while CAS-style checkpoint advancement accepts one progress update and deterministically rejects the racing loser;
- owner/consumer/route/tenant/scope collisions fail closed;
- P04.01 envelope identity, tenant, correlation, causation, schema/classification metadata and payload are not mutated by the durability boundary;
- the reference `MemoryCheckpointStore` is explicitly single-process/test support and is not represented as production-durable storage.

No global ordering or end-to-end exactly-once business-mutation guarantee is introduced.
