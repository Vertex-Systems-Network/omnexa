## Accepted design decision

P03.05 preserved manifest schema v1/v2. Existing manifest `settings` and `feature_flags` entries remain exact fully-qualified configuration-key declarations rather than an encoded mini-language or new schema authority.

Trusted module registration supplies the existing typed `kernel.configuration.Definition`, an explicit `global|scoped` registration scope, and — only for scoped registrations — an existing P02.09 `kernel.configuration.SettingPolicy`.

The P03.05 binder validates declaration ownership, exact key identity, setting-vs-feature-flag class, explicit scope, and scoped-policy validity, then delegates type/default/duplicate authority to the existing `kernel.configuration.NewRegistry`. It does not create a second configuration subsystem.

Validated discovery snapshots retain the accepted setting/feature-flag declarations so configuration binding consumes the same validated module identity source rather than reparsing raw manifests independently.
