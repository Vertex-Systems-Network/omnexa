## Security and architecture invariants

The following are binding:

- health is diagnostic evidence, not authorization or lifecycle command authority;
- required dependency failure is explicit/fail-closed while optional absence is selectively degraded;
- migration ownership/compatibility/pending/failure inconsistency cannot be reported healthy;
- capability/permission/UI availability summaries remain non-authorizing diagnostics;
- health output never includes credentials, secret values, raw tenant/org authority, internal stack traces or unnecessary RESTRICTED data;
- one module failure must not corrupt or suppress unrelated healthy-module reporting where isolation is feasible;
- stable identity/version fields may support later XSG/XPF/XPERF correlation without implementing those systems;
- P01 health/readiness/observability remains the platform foundation rather than being replaced;
- P03.09 migration ownership metadata remains the migration diagnostic source of truth;
- no hidden generic RPC/service-mesh, topology collector, workflow or business-feature runtime is introduced.
