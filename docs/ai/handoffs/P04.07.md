## First-slice contract now present on protected main

### Identity and immutable local registry

`PayloadSchemaIdentity` binds owner + stable event type + positive payload schema version. The payload schema version remains separate from the P04.01 envelope version. The process-local `SchemaRegistry` accepts one immutable canonical fingerprint for one exact identity, returns defensive snapshots, and rejects conflicting same-identity content.

### Canonicalization and fingerprint

Schemas are validated before fingerprint acceptance, copied before normalization, recursively ordered by exact field name, deterministically encoded, and fingerprinted with SHA-256 lowercase hex. Invalid, ambiguous, oversized or structurally unsupported schema input fails closed.

### Compatibility

The accepted first slice exposes `backward`, `forward`, `full`, and `exact` modes only. The predecessor rule is the highest accepted lower version for the same owner/event type. Closed object languages and homogeneous array items are compared recursively. `number` accepts the integer subset; `integer` does not accept general numbers. Compatibility is evidence only and grants no publication, authorization or mutation authority.

### Validation

Validation is synchronous and local. Payloads must be valid UTF-8 JSON root objects and match the exact registered closed schema. Unknown properties, missing required fields, null, duplicate keys, malformed/trailing values, wrong types and unregistered identities fail closed. The frozen limits are:

- schema canonical bytes: 64 KiB;
- schema nesting depth: 8;
- fields per object: 256;
- aggregate schema nodes: 2048;
- field-name length: 128 runes;
- payload bytes: 64 KiB;
- payload nesting depth: 16;
- entries per payload object/array: 256;
- payload string length: 4096 runes.

Validation success is not authorization, business success, inbox completion, checkpoint advancement, retry/quarantine state, exactly-once proof or global-ordering proof.
